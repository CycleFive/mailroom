# Mailroom Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Per-agent mailboxes on Cloudflare: a deterministic poller collects Discord and GitHub activity through the brokers into one inbox per agent, read over MCP with a cursor.

**Architecture:** A Rust Worker (`mailroom-core`, no public URL) holds one SQLite Durable Object per agent and polls on a one-minute cron. A small TypeScript Worker (`mailroom`, the door) does OAuth sign-in and forwards `/mcp` to it. Each broker gains a read-only internal `Feed` entrypoint that the Rust Worker calls over a service binding.

**Tech Stack:** Rust 1.100, `worker` =0.9.0, `serde`, `serde_json` (with `raw_value`), `schemars` 1, `chrono` (no default features); TypeScript 5.9, `@cloudflare/workers-oauth-provider` 1.2.4, vitest 3, wrangler 4.157.

**Spec:** `docs/superpowers/specs/2026-11-18-mailroom-design.md` (read it first; this plan argues from it).

## Global Constraints

- Rust: all wire and stored data are typed serde structs/enums. **Never** `serde_json::json!` or `serde_json::Value` for data mailroom owns. Unparsed sub-documents use `Box<serde_json::value::RawValue>`. Separate enums per direction for request/response protocols. Prefer `&str` in types built and immediately serialized.
- Upstream Discord/GitHub payloads deserialize into concrete structs holding only the fields used, `#[serde(default)]` where a field may be absent. No `deny_unknown_fields` on upstream types.
- Config types use `#[serde(deny_unknown_fields)]`.
- `worker` is pinned exactly: `worker = "=0.9.0"`.
- The logic crate has **no** `worker`, `wasm-bindgen` or `js-sys` dependency and its tests run with plain `cargo test`.
- Traits with async methods use `#[allow(async_fn_in_trait)]` and plain `async fn` (futures are not `Send`; do not add `Send` bounds or `async_trait`).
- Record shape, kinds, tags and ID formats are exactly those in the spec.
- Snowflakes and GitHub IDs are compared as `u64`, never as strings.
- Text is truncated on `char` boundaries, never on bytes.
- Commit messages end with exactly this trailer and no other `Co-Authored-By`:
  `Co-Authored-By: Claude & Lothrop (cycle.five@proton.me)`
- Never copy code from the private `CycleFive/agent-mailbox` repo; the rules to port are written out in this plan.
- No secrets in any file. `wrangler.jsonc` is git-ignored; only `wrangler.example.jsonc` is committed.

## Review Focus

1. **Different-length snowflakes.** A message ID with fewer digits than the watermark must sort below it (numeric, not lexical). Test in Task 3.
2. **Upstream answers with an error or with non-JSON** (Discord's HTML 429). The poll returns `Err`; the caller writes no records and keeps the old state. Tests in Tasks 3, 4 and 6.
3. **Multibyte text at the truncation point.** A 2,001-character body of emoji truncates to 2,000 characters without panicking. Test in Task 3.
4. **Empty message content** (Message Content intent off). The record is still produced with an empty body, and `routed:mention` still works from `mentions`. Test in Task 3.
5. **Client-supplied `x-mailroom-agent` header.** The door replaces it with the grant's agent; a client cannot read another mailbox by sending the header. Test in Task 7.

`Then` serializes as `"drop"` or `{"tag": "x"}`. All config structs carry `deny_unknown_fields`.

Validation rules (each failure names the agent and field in the message):
- agent name: 1–32 chars of `a-z`, `0-9`, `-`
- `broker`: non-empty, only `A-Z`, `0-9`, `_`
- `every_secs` ≥ 60
- Discord `channels`: non-empty, each 5–25 ASCII digits, no duplicates
- GitHub `repos`: non-empty, each `owner/name` with both parts non-empty and no further `/`, no duplicates
- `Then::Tag` and `review_label`: non-empty
- `agents` non-empty

### Task 2: Filter engine

**Files:** Create `crates/logic/src/filter.rs`; Test `crates/logic/tests/filter.rs`.

**Interfaces — Consumes:** `NewRecord`, `Kind`, `Rule`, `When`, `Then`, `Keep` (Task 1).

**Produces:**

```rust
/// Rules first to last, then `keep`. Built-in tags are already on the records.
pub fn apply(records: Vec<NewRecord>, rules: &[Rule], keep: Keep) -> Vec<NewRecord>;
pub fn matches(when: &When, record: &NewRecord) -> bool;
```

Semantics: an empty list in `When` is "no condition"; a non-empty list matches if any element matches. All non-empty conditions must match. `actor` / `actor_not` compare case-insensitively against `record.actor`. `reference` compares exactly. `tag` matches if the record has any listed tag (tags added by earlier rules count). `body_contains` is a case-insensitive substring test over `title + "\n" + body`. `Then::Tag(t)` adds `t` once (no duplicates) and continues; `Then::Drop` removes the record and stops evaluating it. `Keep::Tagged` keeps only records with at least one tag. Order of surviving records is preserved.

```rust
// feed.rs
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct Identity { pub id: String, pub login: String, pub name: String }
#[derive(Debug, Clone, PartialEq)]
pub enum FeedError { Status { status: u16, message: String }, Transport(String), Decode(String) }  // + Display
#[allow(async_fn_in_trait)]
pub trait FeedClient {
    /// GET an upstream API path (e.g. "/channels/1/messages"); returns the response body text.
    async fn get(&self, path: &str, query: &[(&str, &str)]) -> Result<String, FeedError>;
}
pub async fn get_json<T: DeserializeOwned>(feed: &impl FeedClient, path: &str, query: &[(&str, &str)]) -> Result<T, FeedError>;
// A body that is not valid JSON for T -> FeedError::Decode naming the path.

pub struct Poll<S> { pub records: Vec<NewRecord>, pub state: S }
#[derive(Debug)] pub struct PollError(pub String);   // Display; From<FeedError>

// discord.rs
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct DiscordState {
    pub channel_name: String, pub guild_id: String,
    pub watermark: u64,
    /// message id -> emoji key -> reactor user ids
    pub reactions: BTreeMap<String, BTreeMap<String, Vec<String>>>,
}
pub async fn poll_channel(feed: &impl FeedClient, me: &Identity, channel_id: &str, opts: &DiscordSource,
    prev: Option<DiscordState>, now: &str) -> Result<Poll<DiscordState>, PollError>;
```

Algorithm (the tests pin it):

1. `prev == None` (first contact): `GET /channels/{id}` for `name` and `guild_id` (a missing `guild_id` becomes `"@me"`). `GET /channels/{id}/messages?limit=50`. Watermark = highest message ID, or 0 if none. If `opts.reactions`, for every message in the page and every emoji on it, `GET /channels/{c}/messages/{m}/reactions/{emoji}?limit=100` and store the user IDs. Return **no records**.
2. Otherwise fetch page 1 (`limit=50`, newest first). New = ID > watermark. While the page was full (50), every message in it was new, and fewer than 5 pages have been read: fetch `before=<lowest id so far>`. If the fifth page is also full and all new, add one record `kind: Gap`, `id: "dc:gap:{channel}:{newest id}"`, `ts: now`, `actor: ""`, `title: "messages may have been skipped"`, `body: ""`, `url` the jump link of the oldest message read, no tags.
3. For each new message, oldest first: skip if `type` is not 0 or 19; skip if `opts.skip_self` and `author.id == me.id`; otherwise a `Message` record:
   - `id: "dc:{id}"`, `ts: timestamp`, `actor: author.global_name` or else `author.username`, `reference: "#{channel_name}"`, `title: ""`
   - `body`: `truncate(content, 2000, "")`, then if there are attachments append `"\n[{n} attachment(s)]"`, then for each embed with a title append `"\n[embed] {title}"`
   - `url: "https://discord.com/channels/{guild_id}/{channel_id}/{id}"`
   - tags: `routed:mention` if `mentions` contains `me.id`; `routed:reply` if `referenced_message.author.id == me.id`
4. Reactions (if `opts.reactions`), over page 1 only: for each message and emoji whose `count` exceeds the number of stored reactors, fetch the reactors; each user not stored and (unless `!skip_self`) not `me.id` yields a `Reaction` record: `id: "dc:react:{message}:{emoji key}:{user id}"`, `ts: now`, `actor` the user's display name, `reference` as above, `title: ""`, `body` the emoji (`name` for unicode, `:name:` for custom), `url` the message's jump link, no built-in tags. Store the fetched list. The new state keeps reaction entries only for messages in page 1.
5. New watermark = max(old, highest ID seen), counting skipped and self messages.
6. Any `FeedError` returns `Err` — no partial result.

Emoji key: the unicode character, or `name:id` for a custom emoji; percent-encode it for the path.

Upstream types (private, `#[serde(default)]` on optional fields): message `{id, type, timestamp, content, author{id, username, global_name}, mentions[{id}], referenced_message{author{id}}, attachments[], embeds[{title}], reactions[{count, emoji{id, name}}]}`; channel `{name, guild_id}`; reactor `{id, username, global_name}`. IDs arrive as strings and are parsed to `u64`; an unparsable ID is a `PollError`.

**Fake feed** (`tests/support/mod.rs`): `FakeFeed` with `on(path_and_query: &str, body: &str)`, `fail(path_and_query, status)`, and a recorded call log `calls() -> Vec<String>`; keys are `path?k=v&k=v` in the order the poller passes the query. An unregistered path returns `FeedError::Status { status: 404, .. }`. Tests drive futures with `pollster::block_on`.

### Task 4: GitHub repo poller

**Files:** Create `crates/logic/src/github.rs`; Test `crates/logic/tests/github.rs`.

**Interfaces — Consumes:** `FeedClient`, `get_json`, `Identity`, `Poll`, `PollError` (Task 3); `GithubSource`, `NewRecord`, `truncate`, `time::epoch`/`iso` (Task 1).

**Produces:**

```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct GithubState {
    pub last_issue_number: u64, pub last_pr_number: u64,
    pub last_issue_comment_id: u64, pub last_review_comment_id: u64, pub last_event_id: u64,
    /// ISO time of the last successful poll, stored 60 s early.
    pub last_check_at: String,
}
pub async fn poll_repo(feed: &impl FeedClient, me: &Identity, repo: &str, opts: &GithubSource,
    prev: Option<GithubState>, now_epoch: i64) -> Result<Poll<GithubState>, PollError>;
```

Requests, all under `/repos/{repo}` (the repo string as configured):

| # | Path and query | Used for |
|---|---|---|
| 1 | `/issues` `state=all&sort=updated&direction=desc&per_page=50` | issues (entries with a `pull_request` key are skipped) |
| 2 | `/pulls` `state=all&sort=updated&direction=desc&per_page=50` | pulls |
| 3 | `/issues/comments` `sort=created&direction=desc&per_page=50` | issue comments |
| 4 | `/pulls/comments` `sort=created&direction=desc&per_page=50` | review comments |
| 5 | `/issues/events` `per_page=50` | events |
| 6 | `/pulls/{n}/reviews` `per_page=50`, for each pull from #2 with `updated_at > prev.last_check_at` | reviews |

Identity: `bot = me.login` (e.g. `claudeduet[bot]`); `slug` = `bot` without a trailing `[bot]`. "Mentions me" = body contains `@{slug}` case-insensitively. `mine_numbers` = numbers of issues and pulls in #1 and #2 whose `user.login == bot`.

First contact (`prev == None`): run #1–#5, set each watermark to the highest number/ID seen (0 if none), `last_check_at = iso(now_epoch - 60)`, emit **no records**, make no #6 calls.

Otherwise, records (each skipped when `opts.skip_self` and its author is `bot`; watermarks still advance to the highest seen):

| Kind | New when | `id` | `actor` | `title` | `body` | `url` | Tags |
|---|---|---|---|---|---|---|---|
| `Issue` | number > `last_issue_number` | `gh:{repo}:issue:{n}` | `user.login` | title | excerpt of body | `html_url` | `routed:assigned` if an assignee is `bot`; `routed:mention` |
| `Pr` | number > `last_pr_number` | `gh:{repo}:pr:{n}` | `user.login` | title | excerpt | `html_url` | `routed:review` if a label equals `opts.review_label` or a `requested_reviewers` login is `bot`; `routed:assigned`; `routed:mention` |
